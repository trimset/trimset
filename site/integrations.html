Integrations

Change one base URL

The proxy speaks each model's own format and forwards requests unchanged, so your client code stays as it is. The operator names each upstream once on the server; the app only ever sees trimset's URL with its proxy key in the path.

Jev

v0.1

TypeSafe’s hosted decision models. The response names the exact version behind jev-latest, so a silent upgrade is caught on its first answer.

before 
base_url = "https://api.typesafe.ai"
after 
base_url = "https://trimset.example.com/p/tsp_…"
on the server, once 
TRIMSET_UPSTREAM_JEV_URL=https://api.typesafe.ai

Ollaya

v0.1

Open decision models on your own hardware. Its /v1/systemone and its /v1/decisions alias both work.

before 
base_url = "http://localhost:11435"
after 
base_url = "http://localhost:8800/p/tsp_…"
on the server, once 
TRIMSET_UPSTREAM_OLLAYA_URL=http://host.docker.internal:11435

Ollama

v0.1

Decision models through Ollama 0.35 and later, on /v1/systemone.

before 
base_url = "http://localhost:11434"
after 
base_url = "http://localhost:8800/p/tsp_…"
on the server, once 
TRIMSET_UPSTREAM_OLLAMA_URL=http://host.docker.internal:11434

OpenAI decisions

v0.1

OpenAI’s /v1/decisions format: questions as an array, answers in the same order. Errors from trimset itself come back in OpenAI’s error shape.

before 
base_url = "https://api.openai.com/v1"
after 
base_url = "https://trimset.example.com/p/tsp_…/v1"
on the server, once 
TRIMSET_UPSTREAM_OPENAI_URL=https://api.openai.com
TRIMSET_UPSTREAM_OPENAI_FORMAT=openai-decisions

Your app can set headers?

Keep the model's usual path and send the key in a header instead. Your Authorization header then still goes to the model, unless the operator set a model key on the server. trimset never forwards its own key and never follows a redirect.

POST https://trimset.example.com/v1/systemone
X-Trimset-Key: tsp_…
X-Trimset-External-Ref: rf-1001   # optional: your own id
Authorization: Bearer <your model key>
