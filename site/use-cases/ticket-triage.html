Support ticket triage

An online shop routes every incoming ticket to one of four teams. A misrouted ticket waits in the wrong queue and gets passed along. When jev-latest moves to a new version, the probabilities move overnight.

“Which team should handle this ticket?”

The request · POST /v1/systemone

{
  "model": "jev-latest",
  "state": {
    "subject": "Where is my order?",
    "body": "…"
  },
  "questions": {
    "team": {
      "type": "choice",
      "instructions": "Which team should handle this ticket?",
      "criteria": {
        "billing": "…",
        "shipping": "…",
        "returns": "…",
        "tech": "…"
      }
    }
  }
}

The policy

  • top option ≥ tSELECT:<team>route it to that team
  • otherwiseESCALATEa human dispatcher decides
target

Misroutes ≤ 5% among auto-routed tickets, with 95% confidence.

t = [X]: proposed by the refit. A policy is bound to the exact model version, so a new version behind jev-latest gets the default until it is refit.

When the truth arrives

  1. nowRouted to a team, or escalated.proxy
  2. hoursThe team that finally closed the ticket, from the help desk.downstream
  3. 72 hoursNo reassignment: the first routing was right.rule

In your app · Python SDK, gate() from M3

d = ts.gate("team", answer=resp["answers"]["team"],
            model_served=resp["model"], decision_id=ids[0])
if d.action.startswith("SELECT:"):
    route(ticket, team=d.action.removeprefix("SELECT:"))
else:
    dispatcher_queue.add(ticket)
