Refund fraud

An online shop pays refunds automatically. Paying a fraudulent one loses money; holding an honest one loses a customer. The truth comes as a chargeback one to three months later, and a refund that was held almost never learns it.

“Is this refund request fraudulent?”

The request · POST /v1/systemone

{
  "model": "jev-latest",
  "state": {
    "refund_id": "rf-1001",
    "amount": 129.5,
    "reason": "item not received"
  },
  "questions": {
    "refund_fraud": {
      "type": "noul",
      "instructions": "Is this refund request fraudulent?"
    }
  }
}

The policy

  • p < loACCEPTpay out
  • lo ≤ p < hiESCALATEthe risk team decides
  • p ≥ hiBLOCKhold the refund
target

False passes ≤ 2% with 95% confidence, and at most 15% escalated.

lo = [X], hi = [X]: proposed by the refit on your own labels. 1% of accepted refunds are reviewed anyway, so the refits stay honest.

When the truth arrives

  1. nowThe decision is logged with the refund id.proxy
  2. hoursThe risk team’s verdict on escalated and audited refunds.human_review
  3. 30–90 daysA chargeback or a confirmed fraud case.downstream
  4. 120 daysNo chargeback: recorded as not fraud.rule

In your app · Python SDK, gate() from M3

d = ts.gate("refund_fraud", answer=resp["answers"]["refund_fraud"],
            model_served=resp["model"], decision_id=ids[0])
if d.action == "ACCEPT":
    pay_out(refund)
elif d.action == "ESCALATE":
    risk_queue.add(refund)
else:
    hold(refund)
